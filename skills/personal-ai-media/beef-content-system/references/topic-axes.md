# 三层选题扩展框架

## 使用原则

先从原文提取真实素材，再分别从内容、方法、元方法三层寻找新问题。每层最终最多保留 5 个选题。

一个选题只有在回答了原文没有回答的新问题时才成立。不要机械组合所有角度。

## 一、内容层

内容层回答：这件事本身还有什么没有讲完？

内部检查七个问题：

1. 做了什么：具体行动、项目、选择或尝试。
2. 怎么做：执行过程、重要步骤和关键细节。
3. 得到什么结果：变化、数据、反馈或意外。
4. 为什么做：动机、判断、取舍和被放弃的方案。
5. 有什么思考：认知变化、反思和适用边界。
6. 别人如何使用：最小可执行动作、清单或判断标准。
7. 下一步做什么：后续计划、持续验证和新的问题。

七个问题只是内部角度库，不要求逐项输出。优先保留与原文差异最大、用户素材最充分的 5 个。

## 二、方法层

方法层回答：这件事具体是怎么完成的？

优先寻找：

1. 完整流程：从输入到结果经过哪些步骤。
2. 工具分工：不同工具或角色分别负责什么。
3. 关键决策：为什么选择这种做法，而不是其他方案。
4. 判断标准：怎样判断一步已经完成或结果可以使用。
5. 重要环节：哪个步骤最影响结果，哪里最容易出问题。

方法层必须让读者获得可执行的步骤或判断，不能只罗列工具名称。

## 三、元方法层

元方法层回答：这套方法是怎么被找到的？

优先寻找：

1. 起点：为什么开始研究这个问题。
2. 观察：最初记录和关注了哪些信息。
3. 比较：比较了哪些对象、方案或结果。
4. 形成：如何从案例中发现规律并总结成方法。
5. 验证与调整：如何判断方法有效，以及后来怎样修改。

元方法不是更复杂的方法。方法告诉读者“照着做什么”，元方法告诉读者“为什么最后得出要这样做”。

如果用户没有真实的研究、比较、验证或调整过程，不要勉强生成 5 个元方法选题。

## 递归循环

一次真实工作可以依次产生：

```text
事情或结果 → 对它的观点 → 完成它的方法 → 找到方法的过程
```

内容发布或方法使用后出现的新结果，又可以作为新的“事情或结果”进入下一轮。

## 差异检查

生成候选项后依次检查：

- 核心问题是否不同？
- 读者看完后获得的东西是否不同？
- 使用的主要素材是否不同？

如果三个问题中有两个答案相同，优先合并。保留更具体、素材更充分的那个选题。
